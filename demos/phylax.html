Phylax-ops safety-first ops assistant

A retail operations assistant where every answer comes from a tool, and every risky action is gated. A router plans the tool calls, policy questions go to retrieval with sources, SQL passes a read-only guard, and tickets are only created after an explicit confirmation.

About this demo

Honest scope: this page re-implements the repo's mock-mode logic in JavaScript so you can poke at it without a server. The full project is a Python service.

  • Ported faithfully: the rule-based planner (refusals, tool routing, ticket override), the SQL guard rules from app/guards.py (including its forced LIMIT 100), the 6-step tool budget, the one-retry verifier, the confirm-gated ticket tool, and the policy documents and seed formulas.
  • Different here: policy retrieval uses a simple lexical (term-overlap) score over the same paragraph chunks; the repo uses Chroma with all-MiniLM-L6-v2 embeddings. SQL runs on a tiny in-browser engine over generated sample rows; the repo uses SQLAlchemy against SQLite/PostgreSQL with a read-only role and statement timeout.
  • Not used: no LLM planner (the repo can call an OpenAI-compatible model; this demo is the deterministic mock), no LangGraph runtime (the node flow is hand-coded), no FastAPI, no real ticket endpoint. Tickets are simulated locally and nothing leaves your browser.
  • Confidence values are fixed constants in mock mode, not measured scores. No benchmark numbers are claimed on this page.
